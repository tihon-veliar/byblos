# Byblos — Sprint 1 Working Context

## Goal

Implement a deterministic pipeline skeleton:

input → search → context → generate → search → assemble → output

This is NOT a feature sprint.
This is a structural foundation sprint.

---

## Scope

### INCLUDED
- pipeline orchestration
- minimal data contracts
- stubbed search module
- stubbed LLM module
- stubbed link proposal
- CLI runner
- step-by-step logging

### EXCLUDED
- Obsidian integration
- persistence
- real LLM provider
- embeddings
- UI
- performance optimization

---

## Core Principle

One node = one idea  
Nodes must be:
- atomic
- short
- self-contained

---

## Pipeline Flow

Input  
→ normalize  
→ search-1  
→ early duplicate check  
→ context  
→ generate  
→ search-2  
→ final duplicate check  
→ link proposal  
→ assemble  
→ output

---

## Duplicate Model

Two-stage detection:

1. Early duplicate (after search-1)
- if strong match exists → stop pipeline
- decision = duplicate

2. Final duplicate (after search-2)
- if strong match found → stop pipeline
- decision = duplicate

If pipeline reaches link proposal → duplicate is impossible

---

## Decision Model

Final decision is determined ONLY in assemble stage:

- duplicate → nodes = []
- seed → 1 node, no external links
- linked → ≥1 node with external links
- decompose → multiple nodes with internal links

Decision describes result shape, not user action

---

## Data Contracts (Minimal)

Input:
- text

Node:
- id (generated by system)
- title
- content

Match:
- id (existing node)
- title
- score
- type: strong | related

Link:
- source (new node id)
- target (new or existing node id)
- type: extends | refines | contradicts

PipelineResult:
- nodes
- matches
- links (internal + external)
- decision

IMPORTANT:
- these are pipeline contracts
- NOT full note schema

---

## Module Responsibilities

### Core
- orchestrates pipeline
- handles duplicate detection
- computes decision
- assembles result

### LLM
- generates nodes
- proposes links
- NO business logic

### Indexing
- search / retrieval only

### Plugin
- NOT used in Sprint 1

---

## Generation Rules

- may return 1 or multiple nodes
- if multiple nodes:
  - must represent decomposition
  - must be internally linked
- no disconnected node lists

---

## Link Rules

- 1–2 strong links per node
- avoid over-linking
- only meaningful relations

---

## Context Rules

- local only
- max 3–5 nodes
- no global graph

---

## Constraints

- no embeddings
- no global reasoning
- no mutation of existing nodes
- no uncontrolled node explosion
- no cross-layer logic leakage

---

## Logging

Each step must log:
- input
- output
- key decision

Example:
[Search] strong=1 related=2  
[Duplicate] early=true  
[LLM] nodes=2  
[Decision] decompose  

---

## Implementation Rules

- each pipeline step is a separate module/function
- modules must be loosely coupled
- no unnecessary abstractions
- no premature optimization
- no schema enforcement inside LLM layer

---

## What NOT to do

- do not implement real LLM
- do not add persistence
- do not expand data contracts
- do not refactor unrelated code
- do not mix layers

---

## Acceptance Criteria

- pipeline runs via CLI
- no dependency on Obsidian
- deterministic structure
- clear logs per step
- duplicate / seed / linked / decompose all testable

---

## Mental Model

Pipeline is not “smart”.

It is:
- sequential
- explicit
- bounded
- testable

LLM is only a generator, not a decision-maker.

---

## Task Instruction Pattern

When working on a module:

1. Implement ONLY that module
2. Respect contracts
3. Do NOT introduce new abstractions
4. Do NOT modify other modules
5. Keep logic minimal and explicit
